# flow-visualize — .flow → スイムレーンHTML

`.flow`（YAML）を読み、**自己完結HTML（インラインSVG）** のスイムレーン図に変換する。
記法の語彙・意味・描画規約は必ず `docs/SPEC.md` を正とする（このスキルは描画手順のみ）。

## 入力・出力

- 入力：`.flow` ファイルのパス、または DSL テキスト。
- 出力：単一の `.html`（`<title>` ＋インライン `<style>` ＋インライン `<svg>`）。外部依存なし。
- 図は**4ペイン**で出す。**役割（行）と時系列（列）の見出しは固定**し、本体だけがスクロールする（§2.4）。
- 図の下に **凡例（使った要素だけ自動生成）** と、任意で **DSLソースパネル** を付ける。

## 手順

### 1. パース

YAML として読む。`roles` / `timeline` / `steps` を取得。`milestones` / `sla` / `view` / `glossary` / `notes` は任意。
不正・未定義キーは `docs/SPEC.md` の語彙表に照らし、勝手に解釈せず警告として本文に注記する。

### 2. グリッド座標を計算（決め打ち配置）

定数（既定）：

```
LABEL_W = 160      # 左の役割ラベル幅
HEADER_H = 56      # 上の時系列ヘッダ高
LANE_H  = 172      # 1レーンの高さ
COL_W   = 250      # 分岐が無い図の既定。cond/except を自動配置するなら 300 以上（docs/SPEC.md §2.1「列幅の下限」）
NODE_W  = 150 ; NODE_H = 48
```

- `laneTop(i)   = HEADER_H + i * LANE_H`（i = `roles` のindex）
- `laneCenter(i)= laneTop(i) + LANE_H/2`
- `colCenter(j) = LABEL_W + COL_W/2 + j * COL_W`（j = `timeline` のindex。`milestones`/欠番時点は並び順に挿入して採番）
- キャンバス：`width = LABEL_W + COL_W * 列数`、`height = HEADER_H + LANE_H * 行数`（＋下部余白）。
- **座標系は全ペイン共通**。ペインごとの切り出しは `viewBox` で行う（下記）。
  本体の中身の実寸は `BOARD_W = COL_W * 列数`、`BOARD_H = LANE_H * 行数`。
- **セル中心** `cellCenter(役割, 時点) = (colCenter(timeIndex), laneCenter(roleIndex))`。
- **同一セルに複数ノード**：`at` のスロット番号順（無ければ記述順）に、セル中心から縦に等間隔（±40px 目安）で積む（`docs/SPEC.md §2.2`）。
- **最初に列幅を決める**：`.flow` に `at` を持たない `cond` / `except` があれば **`COL_W = 300`**。
  250 のままだと分岐の前後の矢印が片側 4px になり、**線が見えなくなる**（`docs/SPEC.md §2.1`）。
- **`at` を持たない `cond`/`except`/`par`/`join`**：`docs/SPEC.md §2.1` の自動配置に従う（cond/except＝`from` の半列右・同レーン、fork＝`from` の半列右バー、join＝合流ノードの半列左バー）。`at` があればそれを優先。

### 2.5 4つのペインに切り分ける（見出しの固定）

図は **1枚の巨大な SVG ではなく、同じ座標系を共有する4つの SVG** として出す。
こうすると、役割（行）と時系列（列）の見出しを**固定**したまま本体だけスクロールできる。

| ペイン | 目印 | svg の大きさ | `viewBox` | 中身 |
|-------|------|-------------|-----------|------|
| 角 | `{{CORNER}}` | （HTML テキスト） | — | 「役割 \ 時系列」 |
| 列見出し | `{{COLHEAD}}` | `BOARD_W` × `HEADER_H` | `LABEL_W 0 BOARD_W HEADER_H` | 見出しの背景・時点ラベル・マイルストーンのピル |
| 行見出し | `{{ROWHEAD}}` | `LABEL_W` × `BOARD_H` | `0 HEADER_H LABEL_W BOARD_H` | レーンの背景・役割名 |
| 本体 | `{{SVG}}` | `BOARD_W` × `BOARD_H` | `LABEL_W HEADER_H BOARD_W BOARD_H` | レーン背景・列線・マイルストーンの縦線・SLA・ノード・矢印 |

- **`viewBox` で切り出すので、要素の座標は今までどおり**（`colCenter` / `laneCenter` をそのまま使う）。
  ペインごとに座標を計算し直さない。
- **見出しに属する要素を本体に残さない。** ヘッダの帯・時点ラベル・マイルストーンのピル・役割名は
  列見出しと行見出しへ移す。本体に残すと `viewBox` の外で見えないだけで、無駄が残る。
- レーンの背景色は**行見出しと本体の両方**に描く（左右で色が揃うように）。
- テンプレの `--label-w` / `--head-h` / `--board-h` を実寸に差し替える
  （`--board-h` は本体の高さ。画面が狭いときは CSS 側で上限が効く）。

### 2.6 ドラッグで掴んで動かす・拡大縮小する

本体ペインは**左ドラッグでパン**できる（テンプレの JS が担当）。レンダラ側の作業は不要だが、
本体を `id="bodypane"` の中に入れること。列見出し・行見出しのスクロールは本体に追従する。
カーソルは掴める形（`grab` / ドラッグ中は `grabbing`）にする。

**拡大・縮小もテンプレの JS が担当する**（ボタン列と `Ctrl`／`⌘`＋ホイール・ピンチ）。
4ペインは座標系が共通なので、表示サイズと `--label-w` / `--head-h` に同じ倍率を掛けるだけで足りる。
レンダラ側で必要なのは1つだけ：

> **3つの `<svg>` に `width` / `height` 属性を実寸で入れる。** JS はこれを倍率計算の基準に読む。
> 属性が無いと拡大縮小が効かない（`viewBox` だけでは基準の実寸が決まらない）。

`viewBox` は倍率に関係なく固定でよい。倍率ごとに座標を計算し直さない。

### 3. 各ステップをノードに変換

`docs/SPEC.md §5.2` の「種別ごとの見た目」に従って形・色を割り当てる：

- `act` → 青の角丸箱。`by` 前半で 👤/🖥/🔌、`by:外部/…` は水色枠のノードにする。
- `start`/`end` → スタジアム（終了=緑、`view: 例外終了`=赤）。
- `cond` → 黄ひし形、`except` → 赤ひし形。
- `milestone:` の★は、**どのノードの節目か一意に読める位置**（そのノードの枠に接する角）に置く。
  2つのノードやチップの中間に浮かせない。
- ノード内に `act` を主行、`by`/`time`/`freq` を副行。`artifact`＋`op` は緑チップ、`wait` は橙⏳ピル、`issue` は⚠赤帯、`tobe` は紫破線ゴーストで併記。
- **`artifact` がリストなら、成果物ごとにチップを1つずつ縦に並べる**（1行に詰め込まない。`docs/SPEC.md §4.6`）。
  `op` もリストなら順番に対応させ、単一なら全チップで共通にする。
- **`note:` は中立色（青灰）の ⓘ チップ**でノードの下に置く。`issue`（赤）と色を分ける（`docs/SPEC.md §4.7`）。
- **`.flow` の文字列を勝手に短くしない。** 要約・言い換え・句点での打ち切りは禁止。
  入りきらないときは**項目まるごと**を `docs/SPEC.md §5.7` の順で省略し、注記に書く。
  **部分的に切り詰めるのが最も危険**（課題文の後半が落ちて意味が反転することがある）。
  長い文は**折り返して2行**にする（`<tspan>` で改行）ほうが、切るより良い。
- 縦スペースが足りないときの省略順は `docs/SPEC.md §5.7`（tobe → artifact/op → issue を⚠バッジへ → wait を⏳へ）。ノード本体は省略しない。

### 4. エッジ（矢印）を描く

- `from:` の各前ノードのセル中心から当該ノードのセル中心へ、`<path>` ＋ `marker-end` で接続。
- **矢印は文字の上を通さない。** ノードの外にある補足文（`trigger` の説明文など）と線が交差する場合は、
  線を横にずらすか、文を線の反対側へ移す。
- `rework:` → 赤の点線矢印（戻り）。`on_overdue:` → 琥珀の点線矢印＋⏰。
- **`back:` に挙げられた枝は、`rework` と同じ赤い点線で描く**（`docs/SPEC.md §3.3`）。
  ラベルに戻り先を添えてよい（「いいえ（見積もりへ戻る）」）。`back` が無い枝は通常の実線。
- `cond`/`except` の分岐ラベルは、**ひし形の出口の頂点のすぐ外側**に置く（`docs/SPEC.md §5.6`）。
  矢印の中点に置くと、隣の列のノードとの隙間が数 px しかないため置き場所が無く、浮いてしまう。
  **枝の向きとラベルの向きを合わせる**（左へ抜ける枝のラベルを右側に置かない）。線には重ねない。

### 5. v0.2 の制御要素

- `par`（並行開始）：`to:` の対象レーン範囲をまたぐ **slate の縦同期バー** を分岐点に置き、`from` からバー、バーから各 `to` へ矢印。
  **分岐先が `from` と同じ列か左にある場合は矢印が逆行する。** `docs/SPEC.md §2.1`「同列・逆行への対処」に従って
  バー位置をずらす（バーは常に `from` の右、かつ全 `to` の左）。
- `join`：合流点に **slate の縦同期バー**。`join: any` はバーに「○」印。
- **バーに添えるラベルは日本語**（`fork` / `join: all` とは書かない）。`docs/SPEC.md §5.5` の対応表に従う
  （並行開始＝「ここから同時に進む」／`join: all`＝「すべて終わったら次へ」／`join: any`＝「どれか1つ終わったら次へ」）。
- `sla`：`span` の2時点の列位置にまたがる **青ブラケット＋バッジ**（`limit` を表示）。
- `milestones` / `milestone:`：列位置に **紫の破線縦線＋★ラベル**。

### 5.5 用語ツールチップ（v0.3）

本文中の `[[用語]]` / `[[表示\|用語]]` を `glossary:` と突き合わせて置き換える（`docs/SPEC.md §4.5 / §5.8`）。

- SVG では該当部分を `<tspan class="term" data-term="用語" data-desc="説明">表示文字</tspan>` にし、
  **`<title>説明</title>` を必ず同梱**する（JS が動かなくてもブラウザ標準のツールチップで読める）。
- `.term` は点線の下線＋青系の文字色（テンプレの CSS が持っている）。
- **図の下の用語集カードは省略しない。** `{{GLOSSARY}}` に `<dt>用語</dt><dd>説明</dd>` を並べる。
  並び順は `glossary:` の定義順ではなく**図に登場した順**。図で参照していない用語は出さない。
- `glossary:` に無い用語を参照していたら、そのまま文字を出し、注記カードに書く（`docs/SPEC.md §7`）。

### 5.6 補足カード（v0.4）

トップレベルに `notes:` があれば、図の下に「**補足**」カードを作り箇条書きで並べる
（`docs/SPEC.md §5.10`）。凡例・注記とは別カードにする。`notes:` が無ければカードを出さない。

### 6. 凡例を自動生成

その図に実際に登場した要素だけを凡例に出す（`assets/template.html` の凡例スニペット参照）。

### 7. テンプレに流し込む

`assets/template.html` を土台にする（4ペインの枠・見出し固定・左ドラッグ・拡大縮小の JS、凡例/ソースパネルの雛形入り）。
目印は **TITLE / CORNER / COLHEAD / ROWHEAD / SVG / LEGEND / GLOSSARY / SOURCE** の8か所。
あわせて `--label-w` / `--head-h` / `--board-h` を実寸に差し替える。
`glossary:` が無い図では、用語カードごと削除してよい（空の見出しを残さない）。

> **必ず、テンプレ内の HTML コメントを除去してから置換する。**
> コメントには目印の説明が含まれるため、単純な文字列置換をするとコメント内にも本文が流し込まれ、
> さらに挿入した SVG 内のコメントの `-->` で外側コメントが早期終了して**ページ全体がテキストとして表示される**。
> 置換後は「目印が残っていないか」「`<svg>` が1つだけか」「`<svg>` より前に未閉じコメントが無いか」を確認する。

### 8. 破綻チェック（省略不可）

**目視だけで済ませない。次を1項目ずつ確認する。**

**内容の忠実さ**
- `.flow` の全フィールドについて、図に「出ている / 注記付きで省略した」のどちらかになっている。
- 図の文字列が `.flow` の値と**完全一致**している（部分一致で終わっているものは切り詰め＝事故）。

**描画**
- 矢印がテキストを貫通していない。
- 分岐ラベルが**枝の向きと一致**し、線・ノード・チップと重なっていない（`docs/SPEC.md §5.6`）。
- **分岐の前後の矢印が目で見える長さ（20px 以上）ある。** 短ければ `COL_W` が足りない。
- ★マイルストーンが、どのノードの節目か一意に読める。
- ノード・チップ・ピル・ラベルが互いに重なっていない。

**そのほか**

- `.flow` の `artifact` がリストなら、その件数だけチップが出ている（省略したなら注記がある）。
- `back:` の枝が赤い点線で描かれている。`back` の無い枝が赤くなっていない。
- 目印が8か所とも残っていない。`<svg>` は**3つ**（列見出し・行見出し・本体）。`<svg>` より前に未閉じの HTML コメントが無い。
- **見出しが固定されている。** 本体を横スクロールすると列見出しが追従し、縦スクロールすると行見出しが追従する。
- 本体を**左ドラッグ**すると図が動く。ドラッグ中に文字が選択されない。
- **拡大・縮小が効く。** ＋/− で倍率が変わり、どの倍率でも見出しと本体がずれない
  （端まで送ったとき列見出し・行見出しのスクロール位置が本体と一致する）。
- 「幅に合わせる」で図が枠幅に収まり、横スクロールが消える。倍率の表示を押すと等倍に戻る。
- 行見出しのレーン色と本体のレーン色が揃っている。
- `[[` `]]` が生成物に素通しで残っていない（すべて `.term` に置換済み）。`.term` の数と `<title>` の数が一致する。
- 図中に `fork` / `join: all` などの英語専門語が出ていない（`docs/SPEC.md §5.5`）。
- 分岐ラベルが、対応する枝の側にあり、ノード・チップ・矢印のどれとも重なっていない（`docs/SPEC.md §5.6`）。

- ページ本体が横スクロールしない（広い図は `.board` 内だけをスクロール）。
- ノード同士・矢印とラベルが極端に重ならない（重なるなら `COL_W`/`LANE_H` を広げる）。
- **生成 HTML をブラウザで開いて実際に見る。** 座標計算だけで合格にしない。
- 仕上げに **`flow-verify` を通す**（ヒアリング記録があるときは検査B も）。

## 注意

- 省略・代替配置・未対応キーが発生したら、生成物の本文に注記カードを出す（`docs/SPEC.md §7`）。

- 記法にない書式を勝手に足さない。迷ったら `docs/SPEC.md` を参照し、足りなければ本文に「未対応」と明記して描く。
- サブフロー参照・入出力方向・版管理は**初版スコープ外**（SPEC §6）。使われていたら注記のみ。
