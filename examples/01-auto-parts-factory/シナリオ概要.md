# シナリオ① 自動車部品工場：受注 → 出荷

**出典：** 業務ヒアリング（シミュレーション）から起こした例
**話し手：** 工場職員（製造課）／エンジニア（生産技術）
**描いたもの：** 現状フロー（AS-IS）
**規模：** 8役割 × 7列 / 16ステップ

## この業務は何か

自動車メーカーから EDI で確定注文を受け取り、生産計画・部品調達・製造・検査を経て、
製品を出荷し ASN（事前出荷通知）を送るまで。標準リードタイムは 5営業日。

## 範囲

- **始まり：** 自動車メーカーからの確定注文を EDI で受信
- **終わり：** 製品を出荷し、メーカーが受領

## 登場する役割

| 役割 | 区分 |
|------|------|
| 自動車メーカー | 社外（発注元） |
| 受注管理課 | 社内 |
| 生産管理課 | 社内 |
| 調達課 | 社内 |
| 部品サプライヤー | 社外（EDI 連携） |
| 製造課 | 社内 |
| 品質保証課 | 社内 |
| 出荷課 | 社内 |

## このシナリオで使っている記法

ヒアリングから自然に出てきた要素をひととおり含む、実寸大の例：

- **並行と合流** … 計画確定後に「部品発注」と「治具・段取り準備」が同時に走り、両方そろって製造着手
- **条件分岐** … 内示との差異が ±10% を超えたらメーカーへ照会
- **例外分岐** … 検査 NG なら手直しへ
- **やり直し（手戻り）** … 差異照会 → 受注確認へ戻す／手直し → 再検査へ戻す
- **期限（SLA）** … 全体 5営業日、部品納入 1営業日。超過時は納期督促（`on_overdue`）
- **社外システム連携** … EDI 受注 / EDI 発注 / サプライヤー納入 / ASN 送信
- **待ち・滞留** … 回答待ち、部品入荷待ち、検査待ち
- **課題と改善案** … 紙日報・翌朝入力 → MES で実績自動収集（TO-BE）

## 記法検証で分かったこと

この業務フローを書き起こす過程で、記法・スキル側の不具合が4件見つかり、すべて修正した。

| 見つかった問題 | 対応 |
|---------------|------|
| `yes:` / `no:` が YAML で真偽値になりキーが壊れる | `then:` / `else:` に改名（SPEC 3.3） |
| 並行バーが分岐先より右に来て矢印が逆行する | 逆行のない配置が存在しないケースを明記し、列の粒度を割って回避する方針に（SPEC 2.1） |
| 同一セルに2ノード積むと成果物・課題・改善案が描けない | 装飾の省略順を規定（SPEC 5.6）／書き方ガイド（SPEC 2.2） |
| テンプレの解説コメント内の置換トークンまで置換され生成物が壊れる | テンプレからトークン表記を除去／スキルに「置換前にコメント除去」を明記 |

あわせて、図中の文言を日本語に統一する規約（SPEC 5.5）を追加した。
`fork` → 「ここから同時に進む」、`join: all` → 「両方終わったら次へ」など。

**列の粒度について：** 生産計画と部品発注はどちらも Day1 に起きるため、
SPEC 2.2 に従い `Day1` を「午前 / 午後」に割っている。時刻の正確さを保ったまま、
並行開始バーからの矢印が逆行しないようにするため。
