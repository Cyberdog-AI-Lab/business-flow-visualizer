# examples — シナリオ集

1シナリオ = 1フォルダ。各フォルダに、そのシナリオの説明・（あれば）ヒアリング記録・記法テキスト・生成図を置く。

| シナリオ | 内容 | 出典 | 規模 |
|---------|------|------|------|
| [01-auto-parts-factory](01-auto-parts-factory/) | 自動車部品工場（受注→出荷） | ヒアリング（シミュレーション） | 8役割 × 8列 |
| [02-system-development](02-system-development/) | システム開発（開発依頼→納品） | **実際のヒアリング** | 3役割 × 15列 |

- **01** は記法の語彙をひととおり含む実寸大の例。並行・合流・期限・社外連携・用語補足まで入っている。
- **02** は実在の会社の開発プロセスを聞き取ったもの。2段階発注・再提案の戻り・検収のやり直しなど、
  **分岐と戻りが多い**フローの例。所要時間や課題は「聞いていないので空欄」にしてある。

## フォルダの中身

```
{番号}-{シナリオ名}/
├── シナリオ概要.md         この業務は何か・範囲・役割・使っている記法
├── ヒアリング時の会話.md   聞き取りのやり取り（ヒアリング由来のシナリオのみ）
├── *.flow                  記法テキスト
└── *.html                  生成した業務フロー図（ブラウザで開く）
```

- `.html` は `.flow` から `flow-visualize` スキルで生成する。自己完結（外部依存なし）。
- 記法の仕様は [../docs/SPEC.md](../docs/SPEC.md) が正。
